# トピック報告アプリ 導入手順

iPhone / Android のブラウザから使えるトピック報告用Webアプリです。
入力されたデータは、既存の業務日報スプレッドシート（マスターデータ）に
そのまま1行ずつ追記されます。

構成ファイル：

| ファイル | 役割 |
|---|---|
| `index.html` | スマホで開く報告フォーム本体 |
| `Code.gs` | スプレッドシート側に設置するAPI（Google Apps Script） |

---

## 手順 1：スプレッドシート側にAPIを設置する

1. マスターデータのスプレッドシートを開く
2. メニューの **拡張機能 → Apps Script** を開く
3. デフォルトで表示されている `Code.gs` の中身を全て削除し、
   このフォルダの `Code.gs` の内容を貼り付ける
4. 冒頭の `SHEET_NAME` を、実際のシートタブ名に合わせて修正する
   （例のスプレッドシートのタブ名は `業務日報`）
5. 画面右上の **デプロイ → 新しいデプロイ** を選択
   - 種類の選択（歯車アイコン）から **ウェブアプリ** を選ぶ
   - 「次のユーザーとして実行」→ **自分**
   - 「アクセスできるユーザー」→ **全員**
   - **デプロイ** をクリック
   - 初回は権限承認画面が出るので、自分のGoogleアカウントで承認する
     （「このアプリは Google で確認されていません」と出た場合は
     「詳細」→「（プロジェクト名）に移動」と進めば承認できます）
6. 発行された **ウェブアプリのURL**（`https://script.google.com/macros/s/.../exec`）をコピーしておく

> ⚠️ このURLが漏れると誰でもこのシートに書き込めてしまうため、
> 社内での共有範囲には注意してください。より厳密に制限したい場合は
> 「アクセスできるユーザー」を「組織内のみ」に変更するか、
> フォーム側に簡易パスコード認証を追加することもできます（要相談）。

---

## 手順 2：フォーム側にAPIのURLを設定する

`index.html` をテキストエディタで開き、下記の行を探して

```js
const APPS_SCRIPT_URL = "";
```

手順1でコピーしたURLを貼り付けます。

```js
const APPS_SCRIPT_URL = "https://script.google.com/macros/s/XXXXXXXXXXXX/exec";
```

保存して完了です。

---

## 手順 3：スマホから使えるようにする（ホスティング）

`index.html` は1枚のファイルなので、社内の任意のWebサーバー・
GitHubPages・Google サイト等、静的ファイルを置ける場所であれば
どこでも公開できます。すぐに試したい場合は下記いずれかが簡単です。

- **GitHub Pages（無料・推奨）**：GitHubリポジトリに `index.html` を置き、
  Pages機能を有効化するとURLが発行されます
- **社内の共有サーバー**：既存のWebサーバーに置くだけで利用可能
- **Googleドライブ + 簡易ホスティングサービス**などでも代用可

公開後のURLをスマホのブラウザで開き、共有メニューから
**「ホーム画面に追加」** をしておくと、アイコンをタップするだけで
アプリのように起動できるようになります（iPhone / Android共通）。

---

## 音声入力について

- **Androidの標準ブラウザ（Chrome）**：フォーム内の「🎤 音声入力」ボタンが
  使用でき、話した内容がそのまま報告内容欄に入力されます。
- **iPhone（Safari）**：Appleの技術的制約によりこの音声入力ボタンは
  非対応です。代わりに、報告内容欄をタップして表示される
  **画面キーボードのマイクアイコン**（標準のディクテーション機能）を
  使うことで、同様に音声入力が可能です。フォーム側にもその案内が
  自動的に表示されます。

## 入力項目とプルダウンの内容

| 列 | 項目名 | 入力方式 |
|---|---|---|
| A | 報告日 | 日付選択（初期値：当日） |
| B | 報告者 | テキスト入力（候補表示あり） |
| C | 顧客等種別 | プルダウン：既会員法人／新規法人／技能実習生／特定技能外国人／GPO 協力メーカー開発／その他 |
| D | 企業名等 | テキスト入力 |
| E | 事業所名等 | テキスト入力 |
| F | 相手方担当者 | テキスト入力 |
| G | 応対等の方法 | プルダウン：訪問／電話／オンライン／メール・SNS／来社／その他 |
| H | 報告内容 | テキスト入力（音声入力対応、URL自動リンク化） |
| I | （別用途） | このアプリでは使用しません（読み書き対象外） |
| J | 添付ファイルURL 1 | アプリが自動入力（手入力不要） |
| K | 添付ファイル名 1 | アプリが自動入力（手入力不要） |
| L | 添付ファイルURL 2 | アプリが自動入力（手入力不要） |
| M | 添付ファイル名 2 | アプリが自動入力（手入力不要） |
| N | 添付ファイルURL 3 | アプリが自動入力（手入力不要） |
| O | 添付ファイル名 3 | アプリが自動入力（手入力不要） |
| P | 関連報告ID | アプリが自動入力（手入力不要） |
| Q | 関連報告の概要 | アプリが自動入力（手入力不要） |
| R | 報告ID | アプリが自動入力（手入力不要） |

J〜R列は、添付資料・関連付け機能のためにアプリが自動的に書き込む列です。
**I列は他の用途で使用中のため、このアプリは一切読み書きしません**
（新規登録・更新のいずれの処理でも、I列を経由せずA〜H列とJ〜R列だけを
個別に書き込むようにしているため、I列の既存データが上書きされる
心配はありません）。スプレッドシートの1行目に、上記の見出しを
J〜R列にあらかじめ追加しておいてください（無くても動作はしますが、
確認のためにあると分かりやすいです）。

**J〜R列は手入力・修正しないでください。** 内容を書き換えると、
アプリ側で添付資料や関連付けが正しく表示・動作しなくなることがあります。

プルダウンの選択肢を追加・変更したい場合は、`index.html` 内の
`<select>` タグの `<option>` を編集してください（新規報告フォームと、
編集画面・検索条件の両方に同じ選択肢があるため、変更する場合は
該当箇所をまとめて修正してください）。

---

## 動作確認の方法

1. `index.html` をブラウザで開く
2. 各項目を入力し「この内容で報告する」をタップ
3. スプレッドシートに新しい行が追加されていれば成功です

うまく送信できない場合は、Apps Script側の **実行数** または
**デプロイの管理** 画面でエラーログを確認してください。

## 過去の報告の閲覧・検索・編集

画面上部のタブから **「履歴を見る・編集」** に切り替えると、
これまでに報告した内容の一覧・検索・編集ができます。

- **検索条件**：キーワード（企業名・事業所名・担当者・報告内容を横断検索）、
  報告者、顧客等種別、応対方法、期間（から／まで）を組み合わせて絞り込めます
- **一覧タップで編集**：一覧の項目をタップすると編集画面が開き、
  内容を修正して「変更を保存する」でスプレッドシートの該当行を直接更新します
- **最新の状態に更新**：他の人が新しく報告した内容も含めて再取得します
- **URLの自動リンク化**：「報告内容」の中にホームページ等のURL
  （`https://...`）が含まれている場合、一覧上で自動的にリンクとして
  表示され、タップすると新しいタブでそのページが開きます

### 表示される期間について

パフォーマンスのため、「履歴を見る・編集」を開いた直後の**初期表示**は
**直近1か月分の報告のみ**です（画面にもその旨を表示しています）。
毎回全データを読み込むのではなく、対象期間のデータだけを読み込むことで、
報告件数が増えても一覧の表示速度が大きく低下しないようにしています。

- それより古い報告は初期表示には出てきませんが、**スプレッドシート上には
  そのまま残っています**（削除されるわけではありません）
- **検索条件（キーワード／報告者／顧客等種別／応対方法／期間）を
  1つでも入力すると、その時点で対象は「直近1か月」から
  「スプレッドシート全件」に切り替わります**（`action=searchHistory`）。
  1か月より前の古い報告も、検索条件に一致すればきちんとヒットします
- 検索条件をすべてクリアすると、自動的に「直近1か月」の初期表示に戻ります
- 全件検索の結果は、パフォーマンスのため最大300件までに制限しています
  （`Code.gs` の `HISTORY_FULL_SEARCH_LIMIT` で変更可能）
- 初期表示の期間を変更したい場合は、`Code.gs` 冒頭の
  `HISTORY_MONTHS_BACK`（初期値: `1`）の数値を変更してください
  （例: 3か月分にしたい場合は `3` に変更）

### 削除

編集画面下部の **「この報告を削除する」** から、該当の報告をスプレッドシートから
完全に削除できます。誤操作防止のため、保存ボタンとは離れた位置に配置し、
タップ後も確認ダイアログで一度確認してから削除を実行します。
**削除すると元に戻せません**（元に戻す場合はスプレッドシートの変更履歴から復元してください）。

### 同時編集時の競合検知

複数人が同時に同じ報告を開いて編集・削除した場合に、
片方の変更が気づかないまま上書き・削除されてしまわないよう、
以下のように動作します。

1. 編集画面を開いた時点の内容を「元の内容」として保持しておく
2. 保存・削除を実行する際、サーバー側で現在のシートの内容と
   「元の内容」を比較する
3. その間に他の人が既に内容を変更していた場合は **保存・削除を行わず**、
   「他の人が更新しています」という確認画面を表示する
4. 「最新の内容を読み込む」を選ぶと、最新の内容がフォームに反映されるので、
   内容を確認したうえで、あらためて保存・削除をやり直す
5. その間に他の人が既に削除していた場合は、その旨を通知して一覧を最新化する

このため、無条件に上書き・削除されることはなく、必ず最新の状態を
確認したうえで操作できるようになっています。

### Code.gs を更新した場合の注意

既に一度デプロイ済みのプロジェクトで `Code.gs` の中身を更新した場合、
**そのままでは反映されません**。Apps Scriptの画面で
**デプロイ → デプロイを管理 → 既存デプロイの鉛筆アイコン →
バージョン「新バージョン」を選択 → デプロイ** の手順で再デプロイしてください
（ウェブアプリのURL自体は変わらないため、`index.html` 側の再設定は不要です）。

## 添付資料（PDF等）の追加・閲覧

**新規報告** フォームの「添付資料」欄から、PDFや画像ファイルを
**最大3点まで** 添付できます（任意項目、1点あたり10MBまで）。
添付されたファイルは、下記のGoogle Driveフォルダに保存されます。

- 保存先フォルダ：<https://drive.google.com/drive/folders/1OaZGafYb8uKVvgenjxfsFn4YI2Bw04q3>

保存先を変更したい場合は、`Code.gs` 冒頭の `ATTACHMENT_FOLDER_ID` を、
別のフォルダのIDに書き換えてください（フォルダのURLの
`folders/` の後ろの文字列がフォルダIDです）。このスクリプトを実行する
Googleアカウントが、指定したフォルダにアクセスできる状態になっている
必要があります（自分が所有しているフォルダか、共有されているフォルダ）。

- **閲覧**：「履歴を見る・編集」の一覧で、添付が1点だけの報告には
  オレンジ色の「資料を見る」ボタンが表示され、タップすると新しいタブで
  開きます。2点以上ある場合は「資料 2件」のように件数で表示され、
  タップすると編集画面が開いて、資料ごとに個別のリンクから開けます
- **追加・差し替え**：編集画面の「添付資料」欄で新しいファイルを選ぶと、
  空いているスロットに追加されます（既存のファイル名をタップすると、
  そのファイルを新しいタブで確認できます）
- **削除**：編集画面で、各添付ファイルの右にある「✕」から個別に
  削除できます（保存を押すまでは確定しません）
- 報告そのものを削除した場合、添付ファイルもあわせてゴミ箱に移動します
- 最大点数（初期値: 3点）を変更したい場合は、`Code.gs` 冒頭の
  `MAX_ATTACHMENTS` を変更してください。あわせて、スプレッドシート側の
  列（J〜O列は3点分の想定）を増減させる必要があります

### 添付ファイルの共有設定について（重要）

添付ファイルは、保存時に共有設定を **「リンクを知っている全員が閲覧可」**
に変更しようとします。これは、Googleアカウントを持たないスマホからでも
ボタン一つで資料を閲覧できるようにするためです。
**リンクを知っている人は誰でも閲覧できる**ため、社外秘・個人情報等を含む
機密性の高い資料の取り扱いには十分ご注意ください。より厳格な権限管理が
必要な場合は、共有範囲を「組織内のみ」に変更することもできますので、
必要であればご相談ください。

**組織（Google Workspace）のポリシーにより、この「リンクを知っている
全員が閲覧可」への変更自体がブロックされる場合があります。** その場合、
ファイルの保存やスプレッドシートへの記録は正常に行われますが、
実際に開ける人の範囲は、添付ファイルの保存先フォルダ自体に設定されている
共有設定に従います。つまり、**そのフォルダを開ける権限を持つ人だけ**が
「資料を見る」ボタンから開けることになります。社内でこの機能を使う場合は、
添付ファイルの保存先フォルダ自体を、利用者全員が開ける状態に共有して
おくことをおすすめします。

### 添付ファイル付きで送信するとエラーになる場合

**多くの場合、原因はGoogleドライブへのアクセス権限が未承認のままになっていることです。**
スプレッドシートの操作だけならスプレッドシートへの権限だけで動きますが、
添付ファイル機能にはGoogleドライブへの権限も別途必要です。この権限は、
コードを貼り付けてデプロイしただけでは自動的に承認されないことがあります。

1. Apps Scriptの画面を開く
2. 上部の関数選択プルダウンから **`setupAuthorizeAttachments`** を選ぶ
3. **実行**（▷）ボタンをクリック
4. 「権限を確認」→ Googleアカウントを選択 →
   「このアプリは Google で確認されていません」と出た場合は
   「詳細」→「（プロジェクト名）に移動」→「許可」
5. 実行ログに「OK: フォルダにアクセスできました」と表示されれば完了です

この手順を一度行えば、以降はスマホから添付ファイル付きで送信するだけで
正常に保存されるようになります。

それでも解決しない場合は、`?action=debug` にアクセスすると
`driveAccess`（フォルダにアクセスできるか）と`sharingAccess`
（「リンクを知っている全員が閲覧可」への変更が組織のポリシー上できるか）
の項目に、より詳しい原因（`detail`）が表示されますので、その内容を
確認してください。`sharingAccess.ok`が`false`の場合は、報告そのものは
正常に保存されますが、添付ファイルを開ける人の範囲が保存先フォルダの
共有設定に従う形になります（上記「添付ファイルの共有設定について」を
参照してください）。

### 添付ファイルが一覧に表示されない場合

以下の順にご確認ください。

1. **Code.gsを再デプロイしたか**：`Code.gs` を書き換えただけでは反映されません。
   上記の「Code.gs を更新した場合の注意」の手順で、必ず「新バージョン」として
   再デプロイしてください
2. **J列・K列に見出しがあるか**：スプレッドシートの1行目に
   「添付ファイルURL」「添付ファイル名」の見出しがJ列・K列にあるか確認してください
   （無くても動作はしますが、確認のためにあると分かりやすいです）
3. **自己診断機能で確認する**：ブラウザで、Apps ScriptのウェブアプリURLの末尾に
   `?action=debug` を付けて開いてください
   （例: `https://script.google.com/macros/s/xxxxx/exec?action=debug`）
   `version`（現在デプロイされているコードのバージョン）や、
   `headerRow`（1行目の内容。9番目がI列、10〜15番目がJ〜O列＝
   添付ファイル1〜3のURL/名前、16番目がP列＝関連報告ID、
   17番目がQ列＝関連報告の概要、18番目がR列＝報告IDになっているはず）
   が表示されるので、意図した状態になっているか確認できます

### 添付資料の実装メモ（技術者向け）

I列に別用途の既存データが入っている環境を想定し、`sheet.appendRow()` は
使用していません（`appendRow()` はシート全体の最終行を基準に追記するため、
I列の既存データがA〜H列より下まで続いていると、報告データが意図しない
行に書き込まれてしまう可能性があるためです）。代わりに、A列（報告日）の
実データを基準に追記先の行を決めています。

## 過去の報告への関連付け

以前の報告の続き・関連する内容を報告する場合、**新規報告フォーム・
編集画面のどちらからも**「関連する過去の報告」欄で、企業名などを
キーワードに過去の報告を検索し、選んで関連付けることができます。

- この検索は「履歴を見る・編集」の**直近1か月の表示制限を受けず**、
  スプレッドシート全期間が対象です（`action=search`）
- 関連付けると、報告日・企業名などの概要（スナップショット）がQ列に
  保存されます。これは選んだ時点の内容であり、後で元の報告の内容が
  変わっても、この概要表示は追従して更新されません
- 履歴の一覧では、関連付けられた報告に「🔗 関連: ...」という行が表示され、
  タップすると関連する報告の内容をその場でプレビューでき、
  「この報告を編集する」からそのまま編集画面に遷移できます
  （プレビュー・ジャンプは `action=findById` を使い、こちらも
  直近1か月の表示制限を受けません）
- 関連付けは編集画面からいつでも解除・変更できます

### 関連付けたのに開けない・反応がない場合

過去に、関連付け機能を追加する前の `Code.gs` で作成された報告（＝まだ
「報告ID」（R列）が採番されていない報告）を関連付けようとすると、
検索した時点で自動的にIDが採番されるようになっているため、通常は
問題なく機能します。ただし、ごくまれに関連付け先のID（P列）が
空のまま保存されてしまった古いデータがある場合、一覧には関連の表示が
出るのにタップしても何も起きないことがあります。この場合は、
編集画面でその関連付けを一度解除し、あらためて検索して選び直して
ください（現在のバージョンでは、この状態になった場合もタップ時に
「このリンク先は開けません」という案内が表示されるようになっています。
無反応に見える場合は、`Code.gs` が最新版で再デプロイされているか
ご確認ください）。
